# 产品自演进逻辑

## 核心理念

不改代码。靠两层机制驱动产品能力提升。

## 飞轮 1：单租户越用越准

```
用户上传文档 → 编译(Ingest) → 卡片网络变密
                                    ↓
                           同题≥3 → Synth 触发 → 专题档案
                                    ↓
用户查得更准 ← 蒸馏话术精准 ← 知识库变厚 ← MO蒸馏
```

**编译链逻辑不变**（Ingest→Diff→Synth→Distill），但输出的质量随知识密度提升——wikilinks 越密、卡片越交叉验证、专题档案越综合。

## 飞轮 2：跨租户越用越聪明

```
租户A: 金融风控配置 → 验证有效 → 沉淀为"金融"模板
租户B: 政务办公配置 → 验证有效 → 沉淀为"政务"模板
                                         ↓
                    高频配置提取 → 行业默认模板库
                                         ↓
新租户注册 → 选"金融模板" → 30分钟启动 → 不用一月冷启动
```

### 模板包含

| 模板项 | 作用 |
|---|---|
| 信息源列表 | Horizon 爬取什么 |
| 竞品清单 | 竞品 Agent 对标谁 |
| 意图词典 | 语音 Router 的关键词映射 |
| 蒸馏模板 | 输出哪种类型的话术（竞争·趋势·痛点·亮点） |
| 知识库结构 | 预建三层目录 + YAML 模板 |

## 用户可变 vs 不可变

| 可配置（租户自己改） | 不可变（系统锁定） |
|---|---|
| 信息源、竞品名单 | 编译链逻辑 |
| 意图关键词 | Agent 源代码 |
| 蒸馏输出模板 | System Prompt 模板 |
| 行业术语词典 | 安全边界 |
| 知识库组织结构 | 数据模型 |

## 演进路径

```
V1: 租户手动配 YAML
V2: 上传行业文档 → 自动推荐配置
V3: 跨租户高频模式 → 自动生成行业模板
V4: 新租户零配置 → 选行业 → 即时启动
```
