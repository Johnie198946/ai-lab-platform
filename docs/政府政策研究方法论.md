# 中国政府政策研究方法论(云端自生长 v1.0)

> 状态: 2026-08-09 由 Hermes 以研究员身份设计 · 用户拍板为云端知识自生长方向
> 定位: 云端 ai-lab-platform 第一个自生长 Agent 的完整研究方法论
> 底座: 本地 AI 政策雷达(16:30 cron)的实测经验扩展而来

## 一、研究问题(核心关切)

**中国政府正在制定什么政策,将如何影响 AI 产业与算力基础设施?**

三个子问题:
1. **监管与合规**: 数据/算法/AI 治理新规(网信办、工信部、国务院)对超聚变 AI Lab 的业务边界意味着什么?
2. **产业与投资**: 算力基建、芯片、智算中心、东数西算的新政策与资金投向(发改委、财政部、工信部)
3. **信号与商机**: 国资委 100 场景、信创、行业大模型落地政策 → 可转化为 xFusion 商机/话术的信号

## 三、研究流程(每轮执行)

```
1. 探测信源  → 批量 curl 状态码(可达性实测,不假设)
2. 抓取      → 可达信源首页 + 索引页(网信要闻/工信政策通知)
3. 筛选      → 正则提链 + 关键词过滤(AI/算力/数据/算法/监管/智算/芯片)
4. 去重      → 与昨日日报对比,只收新条目
5. 解读      → 每条政策标注: 机构/日期/要点/对超聚变含义
6. 入库      → raw/articles/YYYY-MM-DD-政策研究日报.md
             → wiki/战略信号/ 条目更新(最新在前)
             → knowledge_matrix.json 实体更新
7. 汇报      → 站内通知(平台)/ 后续飞书
```

## 四、日报结构

```
# 政府政策研究日报 YYYY-MM-DD
> 时效窗口 + 信源可达性摘要
## 🔴 今日重大 (≤2条,带为什么重大)
## 🇨🇳 中央政策 (国常会/国务院/两办文件)
## 🏢 部委动态 (工信部/网信办/发改委/财政部/央行/国资委)
## 📡 信号(对超聚变) (3-5条: 政策→商机/威胁/合规要求)
## 来源 (✅可达 / ❌不可达,绝不编造)
```

对超聚变含义锚点: TokenBox(算力)/ TokenOps / AI4MKT / 展厅(物理AI) / 国资委100场景 / 信创。

## 五、研究纪律(硬性)

1. **绝不编造**: 不可达信源标 ❌,薄信源标"低相关仅记录"
2. **反爬不恋战**: 412/401/JS 反爬 → 标记不可达,换信源
3. **时效优先**: 超一周旧文降级"仅记录",不冒充新政策
4. **wiki 通路**: 输出走 wiki 条目更新,不建来源卡片(用户 2026-08 纠正)
5. **每日一次**: 频率固定每日 18:00(与本地 18:30 行业资讯错峰,避免同时段)
6. **增量判定**: 与昨日日报对比,重复条目不重报(至多交叉确认一句)

## 六、落地载体(云端)

- Agent 定义: ai-lab-platform `agents` 表 + `/api/agents`(对话创建/确认/管理)
- 调度: 平台内置调度器(APScheduler,容器内)每日 18:00 触发
- 执行: hermes-bridge → 云端 Hermes(`-p default`)→ 采集+入库+wiki 编译
- 汇报: notifications 表 → web 站内通知中心(红点+列表);后续接飞书 webhook
- 知识: 服务器 vault `/opt/ai-lab-platform/data/vault/`(raw/ + wiki/ + matrix)
