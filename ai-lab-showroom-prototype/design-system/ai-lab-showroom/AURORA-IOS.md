# AI Lab Aurora iOS 设计系统

## 1. 设计理念

这套视觉来自三张参考图的共同语言，但不直接复制具体页面：

- 高白度内容层：主要信息仍落在近白色卡片上，保证展厅远距离阅读。
- 极光氛围层：蓝紫、青、粉只用于背景色雾、重点卡片和主操作，不覆盖大段正文。
- iOS 空间感：依靠大圆角、弱边框、柔和阴影与清晰留白建立层级。
- 克制的玻璃感：导航、浮层、工具条使用半透明与模糊；数据表和长报告保持高不透明度。
- 信息优先：每屏只保留一个最强主行动，颜色不能替代文字、数值或状态图标。

## 2. 交互原则

- 所有触控目标最小 44×44 px，目标间距至少 8 px。
- 按下反馈使用亮度、阴影或 0.98 缩放，时长 160–220 ms。
- 页面切换与弹窗使用 220–280 ms 的淡入和轻微位移，不使用夸张弹跳。
- 状态变化保持空间连续：原位置更新状态，不让卡片跳位。
- 长报告使用章节目录、独立滚动和显式返回；表格在窄屏允许横向滚动。
- 尊重 `prefers-reduced-motion`，关闭非必要动画。

## 4. UI 布局

- 桌面控制台：268 px 侧栏 + 自适应主内容区。
- 展屏画布：以 1920×1080 逻辑比例设计，内容区采用 12 列概念栅格。
- 06 巨幕：左 22–30% / 中 45–53% / 右 24–25%，分别承载上下文、工作内容、讲解与决策。
- 内容最大行长：正文 60–75 个字符；长报告中心栏优先，目录和操作保持窄列。
- Bento 卡片遵循同一视觉基线，避免大小相近但对齐无规律。

## 5. 字体系统

字体栈：`SF Pro Text / SF Pro Display / PingFang SC / Noto Sans SC / system-ui`。

展屏原型采用缩放画布，因此另设可读性下限：微型元信息不得低于 7 px，图注不得低于 8 px，标签不得低于 9 px，正文以 10–12 px 为主；实际 iOS 客户端仍遵循下表的原生字号，并支持 Dynamic Type。

| 层级 | 字号建议 | 字重 | 行高 |
|---|---:|---:|---:|
| Hero | 40–52 px | 700–730 | 1.08 |
| Screen Title | 28–32 px | 700 | 1.15 |
| Section Title | 20–24 px | 680–700 | 1.25 |
| Card Title | 14–18 px | 650–700 | 1.35 |
| Body | 14–16 px | 400–500 | 1.55 |
| Label | 12–13 px | 600–700 | 1.35 |
| Caption | 11–12 px | 500 | 1.45 |

中文不使用过大的字符间距；英文眉题可使用 0.12–0.18 em。

## 6. 间距与栅格

基础单位为 4 px：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`。

- 卡片内边距：紧凑 12–16 px，常规 20–24 px，报告封面 28–32 px。
- 卡片间距：8–12 px；模块间距：16–24 px；章节间距：32–48 px。
- 页面安全边距：手机 16–20 px，平板 24–32 px，展屏 24–40 px。

## 7. 圆角、边框与阴影

- 小控件：12–14 px。
- 输入框与按钮：14–16 px。
- 常规卡片：20–24 px。
- 大弹窗、报告封面：28–30 px。
- 边框默认 1 px，颜色为半透明蓝灰；选中态不改变边框宽度。
- 普通卡片阴影：`0 5px 18px rgba(61,67,126,.08)`。
- 悬浮层阴影：`0 16px 38px rgba(83,91,170,.18)`。
- 大弹窗阴影：`0 32px 100px rgba(37,42,95,.25)`。

## 8. 核心组件规范

- Primary Button：蓝紫渐变、白字、最小高度 44 px，仅用于当前最重要动作。
- Secondary Button：白色或淡蓝紫底、深蓝紫文字、弱边框。
- Glass Card：82% 白色、20–24 px 圆角、轻阴影；仅用于短内容。
- Report Surface：90–100% 白色，禁止大面积透明，支持标题、段落、图、表格和来源。
- Input：近白底、14 px 圆角；聚焦时出现 4 px 淡蓝光环。
- Tab/Segment：灰紫容器 + 白色选中块，不使用满色大底。
- Modal：强模糊遮罩 + 28 px 圆角；必须有显式关闭按钮和 Escape 路径。
- AI Presenter：蓝紫青渐变作为身份线索，字幕使用深靛色高对比底。

## 9. 状态规范

| 状态 | 颜色 | 文案要求 |
|---|---|---|
| Default | 蓝灰 | 显示正常动作名称 |
| Hover/Focused | 蓝紫 | 同时显示边框或焦点环 |
| Pressed | 亮度降低或 0.98 缩放 | 不移动周围布局 |
| Disabled | 45–55% 对比度 | 必须保留禁用原因 |
| Pending | 中性蓝灰 | 使用“待评审/处理中”文字 |
| Approved | 绿色 | 使用勾选图标与“已通过” |
| Changes | 琥珀色 | 使用回转图标与“需修改” |
| Rejected | 玫红色 | 使用叉号图标与“已拒绝” |

## 10. 图标与插画规范

- 图标统一使用 Phosphor 风格的 1.75–2 px 圆角描边 SVG。
- 常规图标 20–24 px，触控区域至少 44 px；同一层级不混用填充与描边。
- 状态图标必须与文字同时出现，禁止仅靠颜色表达。
- 插画采用低细节、圆润几何形、蓝紫青粉配色，人物与设备保持统一视角。
- 背景极光采用 CSS 渐变或矢量，不使用带水印的参考图。
- 图片圆角 18–24 px，并提供有意义的替代文本。

## 11. 禁止项

- 不把所有卡片都做成高透明玻璃。
- 不使用低对比度浅灰正文。
- 不在同一屏出现多个同等级渐变主按钮。
- 不使用 Emoji 充当结构性图标。
- 不复制参考图水印、品牌 Logo 或人物素材。
- 不用大范围霓虹光污染数据表和长报告。
